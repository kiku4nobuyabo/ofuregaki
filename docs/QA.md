# v0.1 検証記録

検証日：2026-09-29。

## 実ブラウザで確認した操作

Chromeで静的アプリを開き、次の内容を操作しました。

- 空欄からタイトル・本文を入力して、プレビューへ即時反映。
- 「重要」を選択して赤ボタン → `&重要&` に変換。
- 直接入力した4色すべての色分け。DOMの色クラス・表示色も確認。
- 本文の実改行が維持され、コピーでは `\n` 形式になること。
- 本文コピー後、実際のクリップボード文字列を確認。
- タイトルコピー後、実際のクリップボードにタイトルだけ入ること。
- 閉じ忘れ警告の表示と、元の記号が維持されること。
- `<img src=x onerror=alert(1)>` を通常文字として表示し、画像要素を生成しないこと。
- 文章の先頭へカーソルを移動 → 座標ダイアログ →「よど城 422,1559」が先頭へ挿入されること。
- 続けてスタンプを選択 → `{13}` がその位置へ挿入されること。
- 下書きの新規保存、読込時の確認、確認後の復元。
- 下書きとマイテンプレそれぞれに独立して保存できること。
- 同一オリジンの別ページで再表示しても、保存件数が維持されること。
- 一門共通テンプレが未登録と表示されること。
- PC幅で左右配置。
- 390px / 320pxのiframe表示で上下配置、ページの横はみ出しなし。
- PC・狭い画面ともプレビュー本文のレイアウト幅が350 CSS px（360pxの領域から安定したスクロールバー領域10pxを引いた幅）で一致。文字サイズ20pxに対して約17.5文字≒約18文字。
- 320px幅でもスタンプダイアログに横はみ出しがなく、ID 30を挿入できること。

`preview-desktop.jpg` は独自の動作確認用文章を入力した画面です。この文章はアプリの初期値・テンプレートには登録していません。

## 自動検証

`node tests/core.test.cjs`：9件、すべて成功。

1. 4色、色内の座標、スタンプの複合解析。
2. 閉じ忘れ・交差指定の警告と文字列保全。
3. CRLF・空行・ゲーム形式の改行変換。
4. 座標の境界判定、小数・負数・3連座標等の除外。
5. HTMLらしい入力がテキストトークンであること。
6. 下書き／マイテンプレの独立した件数上限、11件目拒否、無断削除なし、上書き・削除。
7. 破損JSONや不明なスキーマを上書きしないこと。
8. 保存容量不足を模したエラーの処理。
9. スタンプIDの一意性と共通テンプレの初期状態。

JavaScriptの構文確認、および静的参照ファイルの存在を確認。アプリの実行コードに外部通信APIやユーザー入力をHTMLとして代入するコードがないことも確認しています。

## 未検証・限界

- 実際のゲームへの貼付・投稿は未実施。ゲームとの厳密な表示一致や文字数上限は保証しません。
- スマホ実機のSafari / Android Chrome、OSのクリップボード、ソフトウェアキーボード、IMEは未検証。狭い画面の検証はデスクトップChrome内の幅制約による確認です。
- `file://` での直接起動は構造上対応していますが、今回の実ブラウザ確認はHTTP配信で行いました。
- スタンプ画像未添付のため画像差替え後の実機表示は未確認。フォールバック処理は実装済みです。
- ブラウザのコピー許可拒否時には手動コピー画面へ進む実装ですが、全ブラウザの拒否動作を網羅する検証はしていません。
