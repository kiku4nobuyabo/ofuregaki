# v0.2 検証記録

検証日：2026-09-29。

## 実ブラウザで確認した操作

ChromeでHTTP配信した静的アプリを開き、次の内容を操作しました。

- 初期表示は「エディタ」。再表示時もエディタから開始。
- タイトル・本文を入力してプレビューへ即時反映。
- 本文の「重要」を選択し、下書き・マイテンプレ・一門共通を順に見てエディタへ戻っても、本文と選択範囲が一致。続けて赤ボタンで `&重要&` に変換。
- 直接入力した4色が別々の色クラスで表示されること。
- 「改行」ボタンは文字列末尾へリテラル `\n` を挿入。Enterは実際のLFを挿入。混在した本文をコピーするとゲーム形式へ一度だけ変換。
- 実際の改行へ設定を変えると、クリップボードにLFが入ること。初期形式へ戻せること。
- タイトルコピーにはタイトルだけが入ること。
- 座標入力欄の初期値はすべて空。汎用placeholderを確認し、名前を省略して座標を挿入。
- `725,1647` をプレビューでは `📍(725,1647)` と表示。原稿と実際のコピー内容は元の数値表記のまま。
- 閉じ忘れ警告を表示し、元の記号を保持。
- `<img src=x onerror=alert(1)>` を文字として表示し、画像要素を生成しないこと。
- パレット内145件、末尾ID 145の選択と `{145}` の挿入。モーダル全体の高さが制限され、一覧部分の内容だけが縦スクロールすること。
- 下書き・マイテンプレへそれぞれ新規保存。
- 一覧のアコーディオンを展開し、名前・御触書タイトル・本文・日時・開く／削除ボタンを表示。
- 保存済み原稿を開くとエディタへ移動し、実改行とリテラル `\n` を含む元の本文を復元。
- 未保存変更があると読込前に確認。キャンセルで現原稿を保持し、許可すると復元。
- マイテンプレの削除確認と削除結果。下書きの件数は変わらないこと。
- 同じオリジンで再表示しても保存件数が維持されること。
- 一門共通テンプレは未登録表示。利用者による削除・編集ボタンがないこと。
- ヘルプの6手順、Discordの依頼先、保存の説明、構文表が利用者向けの文章であること。
- PCは左右配置。390px / 320pxのiframeでは上下配置。
- 390px / 320pxのiframeで、実効表示幅375px / 305pxとページのscrollWidthが一致し、横はみ出しなし。
- 320px幅の下書き展開・読込・スタンプ選択・×による閉じる操作・削除が使用可能。
- 320px幅でもスタンプパレットは145件、末尾へ到達して選択可能。パレットの表示幅とscrollWidthが一致。

`preview-desktop.jpg` は独自の確認用文章を入力したv0.2画面です。この文章や確認用の保存データは、アプリの初期値・テンプレートには登録していません。

## 自動検証

`node tests/core.test.cjs`：11件、すべて成功。

1. 4色、色内の座標、スタンプの複合解析。
2. 閉じ忘れ・交差指定の警告と文字列保全。
3. CRLF・空行・ゲーム形式の改行変換。
4. 座標の境界判定、小数・負数・3連座標等の除外。
5. HTMLらしい入力がテキストトークンであること。
6. 下書き／マイテンプレの独立した件数上限、11件目拒否、無断削除なし、上書き・削除。
7. 破損JSONや不明なスキーマを上書きしないこと。
8. 保存容量不足を模したエラーの処理。
9. スタンプIDの一意性と共通テンプレの初期状態。
10. v0.1の保存キー・スキーマとの互換性、実改行とリテラル改行の保存・読込。
11. パレットのID 1〜145が連続し、末尾が「禁」であること。

JavaScriptの構文、静的参照ファイルの存在、ZIPの整合性も確認しています。実行コードに外部通信APIやユーザー入力をHTMLとして代入するコードはありません。

## 未検証・限界

- 実際のゲームへの貼付・投稿は未実施。ゲームとの厳密な表示一致や文字数上限は保証しません。スタンプID定義の根拠と照合範囲は `REFERENCE.md` を参照してください。
- スマホ実機のSafari / Android Chrome、OSのクリップボード、ソフトウェアキーボード、IMEは未検証。狭い画面の検証はデスクトップChrome内の幅制約による確認です。
- `file://` での直接起動は構造上対応していますが、今回の実ブラウザ確認はHTTP配信で行いました。
- スタンプ画像は未添付です。画像差替え後の表示や全ブラウザのコピー許可拒否動作を網羅する検証はしていません。
- 一門共通テンプレの実データは空です。共通項目の表示は下書き等と同じ描画関数を使用します。
